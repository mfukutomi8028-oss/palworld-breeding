# v114 実装プロンプト

## 目的
v113で追加したPalDB由来のパートナースキル画像・属性画像・ドロップ表示について、実画面で確認された表示崩れとデータ解釈ミスを修正し、PalDBの現行表示内容を正しく反映する。

## 前提
- 既存Firebase Realtime Databaseのルーム／配合記録スキーマは変更しない。
- `#room=...` 共有方式、既存配合計算、ヒント、比較機能を壊さない。
- PalDB由来の画像は公開時に外部CDNへホットリンクせず、既存の `assets/paldb-ui-v113/` 配下へローカル固定する。
- 既存のv111/v112/v113自動テストを維持し、今回の不具合を再発させない回帰テストを追加する。

## 修正要件

### 1. パートナースキル画像の視認性修正
- 一部のPalDBパートナースキルアイコンは白いシルエット画像で、現行UIでは白い面が強く出て「白く塗りつぶされた」ように見える。
- ブラウザのドラッグプレビュー時のように輪郭・抜きが判別できる濃度へ調整し、暗色UI上でも形状を視認できるようにする。
- 画像の長押し／ドラッグを前提とせず、通常表示だけで判別できること。
- 画像の誤ドラッグを防ぐため `draggable=false` と `user-select:none` / `-webkit-user-drag:none` を適用する。
- アイコンが取得できない場合の文字／記号フォールバックは残す。

### 2. 属性アイコン巨大化の修正
- `.pal-detail-hero img` の150px指定が属性アイコンにも波及しているため、パル図鑑右側詳細と個別詳細ページで属性アイコンが巨大化している。
- パル本体画像の150px表示は維持する。
- 属性アイコンはタグ内の小型アイコン（概ね17〜20px）として固定し、`margin`、`filter` 等もパル本体画像用CSSの影響を受けないようにする。
- 作業適性・アイテムアイコンの既存サイズは変えない。
- PC、390px幅モバイルの両方で横あふれを発生させない。

### 3. PalDBドロップ情報の再取得・正規化
現行パーサーはPalDBの `Possible Drops` 行を「アイテム名 + 数量 + レベル + 確率」の構造として扱えておらず、例として `古代文明の朽ちた遺物 1–10` をアイテム名、`70` を数量として保存している。これを根本修正する。

各ドロップ行について最低限次を保持する。
- `item`: アイテム名のみ。数量・レベルを混ぜない。
- `quantity`: 数量または数量範囲（例 `1–3`, `1`, `30–50`）。
- `probability`: 確率（例 `100%`, `3.33%`）。
- `level`: 条件レベル。無条件行は空文字、条件行は `70`, `80` 等。
- `conditionIcon`: PalDBのレベル欄等に表示される追加条件アイコンがあれば画像URL／ローカルパス。
- `isBoss`: ボス条件と判定できる場合は `true`。
- `icon`: アイテムアイコン。
- `sourceUrl`: アイテム詳細URL。

### 4. ドロップパース方式
- アイテム名は数量文字列から逆算せず、原則として行内のアイテムリンク文字列から取得する。
- 行全体の数値列を解析し、確率を除いた最初の値を数量、次の値を条件レベルとして扱う。
- レスポンシブ用の重複表示文字がHTML内に存在しても、同じ値の重複で列がずれないように正規化する。
- アイテムアイコン以外の行内画像がある場合は追加条件アイコン候補として保持する。
- 全299体をPalDBから再生成し、既存の誤パース済み固定データを置換する。

### 5. リリクイン固定検証
PalDB現行ページを基準に、リリクイン（Lyleen）で少なくとも以下を自動検証する。
- 無条件: 高品質な回復薬 / 数量1–3 / 100% / level空。
- 無条件: きれいな花 / 数量1–2 / 100% / level空。
- 無条件: 革新的な技術書 / 数量1 / 10% / level空。
- Lv.70: 世界樹の聖水 / 数量1–3 / 50% / level=70。
- Lv.70: 古代文明の朽ちた遺物 / 数量1–10 / 10% / level=70。
- Lv.80: 草の輝石 / 数量10–20 / 100% / level=80。
- Lv.80: 古代文明の朽ちた遺物 / 数量30–50 / 100% / level=80。
- Lv.80行でPalDB由来の追加条件マークを保持・表示できること。
- `item` に `1–3` や `1–10` 等の数量が混入していないこと。

## UI表示
- ドロップ行は「アイコン / アイテム名 / 条件（Lv.xx + 条件マーク） / 数量 / 確率」が判別できる構成にする。
- 無条件行では条件欄を空にして不要なノイズを増やさない。
- 条件レベルは `Lv.70` のように表示する。
- 条件アイコンがある場合はレベルの横に小さく表示する。
- モバイルでは重要情報を消さず、必要に応じてメタ情報を折り返す。
