# v117 実装プロンプト

## 目的
配合記録のタマゴ選択において、明示的な「未設定」が保持されず直前の選択値へ戻る不具合と、新規配合記録を開いた際に前回入力したタマゴが残る不具合を修正する。

## 前提
- Firebase Realtime Database、`#room=...`、既存配合記録、配合検索、配合ヒント、パル図鑑、比較機能の保存形式は変更しない。
- v112で導入した「通常 / デカ / キョダイ → 種類9個」の2段階タマゴ選択UIを維持する。
- 突然変異タマゴのロック挙動と既存編集時のタマゴ復元を維持する。
- サイト版はv117とし、README / CHANGELOG / キャッシュバスターの整合性を維持する。

## 不具合の原因
現行 `syncEggSelection(value)` は `value || button.dataset.value || ''` で値を決定している。このため空文字 `''` を「未設定」という明示的な値として渡しても falsy と判定され、直前の `button.dataset.value` を再利用してしまう。

その結果、以下の2症状が同一原因で発生している。
1. タマゴ選択画面で「未設定にする」を押しても、直前に選択していたタマゴが残る。
2. タマゴを設定した記録の後で「新しい配合記録」を開くと、前回のタマゴが新規フォームへ残る。

## 実装要件
### 1. 未設定を明示的な値として扱う
- `syncEggSelection('')` は必ず `data-value=""` にする。
- 空文字を以前の値へのフォールバックとして扱わない。
- タマゴ表示は「タマゴを選択」の未設定状態へ戻す。
- 「未設定にする」クリック後はダイアログを閉じ、登録フォーム上でも未設定であることを確認できる。

### 2. 新規配合記録の初期化
- `openRecordDialog()` を新規モードで開いた場合、タマゴ値は必ず空から開始する。
- 前回の新規登録、編集、キャンセル等で残ったDOMの `data-value` を引き継がない。
- 親A / 親B等の明示的なprefillは従来どおり利用できる。
- `prefill.eggType` が明示された場合だけ、その値を初期値として使用する。

### 3. 既存編集と突然変異を壊さない
- 既存レコード編集では保存済みの `eggType` を正しく復元する。
- 突然変異チェック中は通常タマゴ選択をロックし、保存時の `eggType` は空とする既存仕様を維持する。
- 突然変異を解除したときの通常タマゴ選択UIが破綻しないこと。

### 4. バージョン管理
- `window.palSiteVersion` を117へ更新する。
- READMEの現行版をv117へ更新する。
- CHANGELOG先頭へv117を追加する。
- v117の修正スクリプトをキャッシュバスター付きで読み込む。
- サイト版整合性CIをv117でも通す。

## QA / 回帰テスト
最低限、ブラウザテストで次を確認する。
1. 新規フォームを開くとタマゴ値は空。
2. 任意のタマゴを選択すると `data-value` にその名称が入る。
3. 再度タマゴ選択を開き「未設定にする」を押すと `data-value` が空になる。
4. その状態で保存対象へ渡されるタマゴ値も空である。
5. タマゴを選択した状態でフォームを閉じ、新たに「新しい配合記録」を開くとタマゴ値が空に戻る。
6. 既存レコード編集では保存済みタマゴが復元される。
7. v112〜v116の既存回帰テストをすべて通す。
8. 390px幅で既存UIを壊さない。
