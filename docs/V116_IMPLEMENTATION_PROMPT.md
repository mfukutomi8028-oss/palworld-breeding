# v116 実装プロンプト

## 目的
配合ヒント・パル比較・サイトバージョン管理・GitHub READMEの4点について、現行機能やFirebaseデータを壊さず、UIの一貫性と保守性を改善する。

## 前提
- Firebase Realtime Database、`#room=...`、既存配合記録、配合計算、パル図鑑、比較選択データの保存形式は変更しない。
- v111〜v115で追加したパル詳細、PalDB固定データ、アイコン、詳細ページ深リンク、左メニュー遷移修正を維持する。
- PCと390px幅モバイルの双方で回帰確認する。

## 1. 配合ヒント4・日本語名の×開示をヒント3と統一
現状、ヒント4では名前が存在しない位置が最初から赤い `×` で表示され、クリックできない。一方、ヒント3のローマ字子音は全枠が最初は `?` で、クリックして初めて文字または赤い `×` を確認する。

### 要件
- ヒント4も、名前が存在しない位置を含めて最初はすべて `?` とする。
- 各カードをクリックした後にだけ、その位置の日本語1文字または赤い `×` を表示する。
- `×` を開示したカードはヒント3と同様に赤系の枠・背景・文字で表現する。
- 一度開示したカードは再クリック不要となるよう無効化する。
- 順方向ヒント、逆引きヒントの双方へ適用する。
- 有効な文字位置の開示、ヒント進捗保存、答え表示など既存挙動を壊さない。

## 2. パル比較トレイをパル図鑑以外で表示しない
現状、比較対象を1体以上選択したまま左メニューから別画面へ移動すると、`body` 直下にある比較トレイが画面下部へ残り続ける。

### 要件
- 比較トレイはパル図鑑を表示しているときだけ表示する。
- 左メニューで配合記録、配合検索、ヒント、確認作業、お気に入り、設定などへ移動した場合は即座に非表示にする。
- 比較選択そのものは解除しない。パル図鑑へ戻れば以前の選択をそのまま再表示できること。
- 比較ダイアログ・比較追加/解除・最大3体制限・localStorage保存形式は変更しない。
- 画面遷移時にレイアウトジャンプや横オーバーフローを発生させない。

## 3. サイトバージョンをv116へ更新し、表示版を一元管理する
現状、設定画面が参照する `config.js` の `palSiteVersion` が110のまま残っている。`app-core.js` 内の旧 `VERSION` はローカルキャッシュキー等に使われる内部スキーマ番号で、公開サイト版とは役割が異なるため、表示版と混同しない。

### 要件
- 今回の公開サイト版を `116` とする。
- 表示用サイトバージョンは `config.js` の `window.palSiteVersion` を唯一の基準とする。
- 設定画面の「サイト版」は `window.palSiteVersion` を表示し、`v116` になること。
- `app-core.js` の旧 `VERSION` は既存キャッシュ互換の内部値として扱い、公開サイト版の表示には利用しない。
- `config.js` / `app-core.js` の読み込みキャッシュバスターをv116へ更新する。
- 今後のリリースで更新漏れを防ぐため、CIで以下を検証する。
  - `config.js` のサイト版
  - `index.html` の主要キャッシュバスター
  - READMEの現行版表記
  - CHANGELOGの最新見出し

## 4. READMEを現行仕様中心へ再構成し、更新履歴をCHANGELOGへ分離
現行READMEは先頭がv7のまま、各バージョンの変更内容を本文へ追記し続ける旧形式で、現在のサイト仕様を把握しにくい。

### 方針
READMEは「現在のプロジェクトを理解し、利用・保守するための入口」とする。全バージョンの詳細履歴をREADMEへ積み上げない。

### READMEに記載する内容
- プロジェクト名と現行サイト版 v116
- サービス概要
- 現在の主要機能
- ルーム共有方式 `#room=...`
- Firebase Realtime Database利用
- GitHub Pages公開方式
- Palworld 1.0 / 299体データ対応
- 主要なデータ出典と固定データ方針
- 開発・検証方法の概要
- 更新履歴は `CHANGELOG.md` へのリンク
- 過去の詳細はGit履歴から確認できる旨

### CHANGELOG
- 新規に `CHANGELOG.md` を作成する。
- 最新版を先頭に置く。
- v110〜v116は現在の構成へ至る主要リリースとして整理する。
- v109以前は旧README・Git履歴に多数の細かな更新が存在するため、虚偽の完全履歴を作らず「Legacy history」としてGit履歴を参照する旨を明示する。
- 今後は各リリースでCHANGELOGへ1セクション追加する運用とする。
