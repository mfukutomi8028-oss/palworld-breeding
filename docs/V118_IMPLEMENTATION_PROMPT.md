# v118 実行用プロンプト

## 目的

既存の「自分たちで発見した配合を記録・共有する」体験を壊さず、発見済みパルの育成判断に必要な情報をパル図鑑内で完結させる。

## 背景

- 現行v117ではPalDB由来の種族値・パートナースキル概要・移動性能・ドロップ等を表示済み。
- Palworldには★0〜4のCondensationがあり、HP・攻撃・防御、パートナースキル、★4時の作業適性が変化する。
- 各パルにはLv習得スキルがあり、レベル、属性、威力、CT等を比較したい。
- パル図鑑では作業適性の種類を絞り込めるが、Lvの高低での並び替えが必要。
- モーダルは×/キャンセルだけでなく背景クリックでも閉じたい。

## 維持必須

- Firebase Realtime Databaseの既存ルーム・配合記録・ユーザー・お気に入り。
- `#room=...` と `#room=...&pal=...` のURL方式。
- 発見記録モードと隠し全パル解放。
- v111〜v117のパル詳細、比較、ドロップ、アイコン、タマゴUI等。
- GitHub Pagesの静的構成。

## 実装要件

1. PalDB日本語個別ページから299体について、Partner Skill Lv1〜5を★0〜4へ対応付けた固定データを生成する。
2. 例としてデスティングは★0〜4で防御5/6/7/8/10%、雷属性ドロップ40/50/60/70/80%であることを自動検証する。
3. PalDBのActive Skillsから自然習得Lv、名称、属性、威力、CT、専用/状態効果を固定データ化する。
4. パル詳細に★強化シミュレーターを実装する。共通ステータス補正は★1〜4で+5/+10/+15/+20%。作業適性は現行1.0仕様に従い★4時に全既存適性+1とする。
5. 種族値HP/攻撃/防御/合計へ299体中の順位を表示する。同値は同順位の競技順位方式とする。
6. パル図鑑へ作業適性Lvの高い順/低い順を追加する。特定作業適性を選択中はその適性Lvを基準にする。未選択時は最高作業適性Lvを使う。
7. 作業適性並び替え中は、何Lvで並んでいるかカード上に補助表示する。
8. 全`dialog`で、フォーム外側のbackdropクリック時に`close()`し、×/キャンセルと同じキャンセル動作にする。フォーム内クリックでは閉じない。
9. UIは情報を詰め込みすぎず、★はタブ、スキルは折りたたみ＋絞り込み、順位は既存種族値カード内の補助情報として配置する。
10. 外部PalDBはビルド時の取得元とし、公開サイトは固定JSONを読み込む。

## データ品質

- `data/pal-growth-v1.json`は299件。
- Partner Skill ★データは299/299体、各5段階。
- Active SkillsはPalDB上に自然習得スキルがある全パルを取得し、取得不能/データなしは推測で補完しない。
- Lv6以上等、★0〜4の範囲外となるPartner Skillデータを★4へ混入させない。
- 長文説明は転載せず、名称・数値・CT・威力・状態タグ等の構造化事実だけを保持する。

## 受入試験

- モコロン種族値: HP70 / 攻撃70 / 防御70 / 合計210。
- モコロン: Lv40 パワーボム CT8 威力120、Lv50 パルブラスト CT20 威力450、Lv70 ホーリーバースト CT30 威力700。
- デスティング: ★0 雷ドロップ40%・防御5%、★4 雷ドロップ80%・防御10%。
- デスティング: Lv40 ロックランス CT20 威力400。
- ★0〜3では作業適性Lvを変えず、★4で既存の全作業適性が+1表示になる。
- 種族値4項目すべてに順位が出る。
- 作業適性の昇順/降順が正しく、選択中の作業Lvがカードに表示される。
- 親パル選択・タマゴ選択・ユーザー設定・比較等の主要dialogがbackdropクリックで閉じる。
- PC 1440px、モバイル390pxで横スクロールや操作不能がない。
- 既存v117回帰テストがすべて成功する。
- mainマージ後、GitHub Pagesで`palSiteVersion = "118"`と新機能の実表示を確認する。

## 禁止事項

- Firebase実データをテストで削除・変更しない。
- Partner Skillの数値を推測しない。
- PalDB長文をそのまま大量転載しない。
- ★1〜3で作業適性が上がると誤表示しない。
- 新機能のために発見記録モードのネタバレ制御を解除しない。
- CSSでエラーを隠すだけの対応をしない。
